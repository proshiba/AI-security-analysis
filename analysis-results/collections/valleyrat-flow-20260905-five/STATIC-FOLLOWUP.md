# 追加5検体の通信フロー解析：途中経過

## 結論

2026-09-05、MalwareBazaarのValleyRAT報告ラベルで照会した最新100件から、既存ケースにない実行形式5件を取得しました。5件とも終端モジュールの登録手順・生存通知周期は未解決です。取得成功を解析完了とせず、`analysis_followup_pending`で登録しています。整理先ファミリーは提供元報告によるもので、内部静的帰属は未確認です。

Kaliで暗号化ZIPを認証・展開し、内側の完全SHA-256を照合しました。標準`analysis_job_runner.py`は5件を処理し、解析器の強制選択をせず未完了で終了しました。その後Ghidra 12.1.1のヘッドレス解析で全発見関数を目録化し、414関数の逆コンパイルを試行、413関数で成功しました。全関数の意味レビュー完了を意味しません。MCP接続先がないためヘッドレス機能を使用し、MCP成功とは記録していません。

## 13b5検体で確認できた通信までの処理

| 関数 | コードを追って確認した内容 | 通信タイミングへの意味 |
|---|---|---|
| `FUN_00401000` | XOR `0xb1`でAPI名を復元。`kernel32.dll`、`LoadLibraryA`、`GetProcAddress`を実データと照合 | 動的API解決。heartbeatとは無関係 |
| `FUN_00401b80` | `wininet.dll`、`InternetOpenA`、`InternetOpenUrlA`、`InternetReadFile`、`InternetCloseHandle`を復元。HTTPで4096-byte chunkをEOFまで読み累積 | 後段downloaderであり、RATのtask受信loopではない |
| `FUN_00401f70` | API初期化、URL復元、download、受信size判定、例外handler登録を行う | download後の終端挙動は未確認 |
| `FUN_00401e30` | access violationを条件に`VirtualAlloc`と受信データ複写、例外contextの実行先変更へ進むコード | 検体には後段実行経路がある。解析環境では実行しない |
| `FUN_00401190` | file削除の再試行に300 ms待機、上限20回 | C2 heartbeatの300 ms周期と解釈してはいけない |

これらは検体の静的所見です。受信ペイロードや例外処理を解析環境で起動していません。API名の復号はPEの仮想アドレスからファイル内位置への変換と固定XORのみで、CPUエミュレーションを使っていません。生の逆コンパイル全文は非公開領域に保存し、公開ケースの標準関数レビュー契約への統合は未完了のままです。

## 次に必要な解析

1. 13b5の取得する後段を、完全hashに紐づく保存済み成果物から取得し、静的解析する。配布URLへ接続しない。
2. 残る保護PEでは、選定済み関数の未解決call・復元bufferの由来を優先して追う。単に選定数を増やすだけでは完了としない。
3. 終端モジュールの登録データ生成、コマンド分配、タイマー呼出しと、同一ハッシュのPCAPを相互確認する。

既知Winos終端の完全ハッシュ3件をMalwareBazaarで追加照会しましたが、いずれも`hash_not_found`でした。保存済み非公開解析アーカイブの復元は未実施です。追加の[配布イメージ解析](../valleyrat-flow-20260905-img/STATIC-FOLLOWUP.md)は本5件を置き換えず、独立に保持しています。
